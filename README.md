# ぴつじ脱出ゲーム 試作（操作パート1〜8 ＋ ストーリーパート1〜8）

設計資料（`設計資料/` フォルダ）に基づく試作です。スタートからエンディングまで通して遊べます。
背景の一部・アイテム・調査ノート等の画像は未確定のため、文字のプレースホルダーで表示しています
（不足している画像・SE・BGMは `設計資料/設計時メモ/不足素材一覧.txt` を参照）。

## 動かし方

`fetch()` でJSONを読み込む構成のため、`index.html` を直接ダブルクリックして
開くとブラウザのセキュリティ制限で読み込みに失敗します。
任意のローカルサーバーを使用して、このフォルダ（index.html がある場所）を配信し、
スマホ/PCブラウザでそのURLを開いてください。

## 実装範囲

- 操作パート1〜8 ／ ストーリーパート1〜8 ／ 仮のエンディング画面（「おしまい」＋「タイトルへ戻る」）
- 画面遷移：矢印／ズーム／ドア移動／調査ノート（ページ送り）／モーダル（ギミック・ログ・ヒント・設定・画像表示）
- アイテム：取得（入手時に拡大画像を表示・タップで閉じる）・選択・拡大表示（説明文付き）・使用（消失／変化／残存）／パート切替時の残存アイテム自動破棄
  （使える場所は `items.json` の `usableOn`。それ以外の場所(不正解位置)では消費しない）
- ギミック：ドアBの電子錠（数字4桁）／玄関の電子錠（文字選択）／チャット画面（送り先の選択＋ランキング表示・穴埋め選択・写真添付）／電話（番号入力）／写真ギミック（写真上のマラカス・タンバリンをタップ）
- ストーリー：背景画像（ぴつじの部屋・配信画面・机）と立ち絵（配信画面越しに話す黒ぴぐまは立ち絵なし）、BGMの切替・停止
- 操作パート6のみ、クリア条件を満たすと配信ボタン無しで自動的にストーリーへ進む
- ヘッダーのゲームタイトル（プロローグ終了後に「ぴつじを部屋から脱出させるゲーム」へ変わる）
- ストーリーの早送り（1行ずつ高速で自動送り。もう一度押すと停止）
- オートセーブ／オートロード（localStorage）
- ヒント・ログ・設定の簡易モーダル
- SE・BGM（設定画面で音量を 大・中・小・消 から選択。初期値は中）、設定画面に著作権表記
- ストーリーで流れたBGMはオーディオで選べるようになり、次の操作パートの開始時メッセージの後に「BGM 〇〇 がオーディオに追加された」と表示

## SE・BGMの設定

- 音声ファイルの割り当ては `data/audio.json` に集約しています（キー名 → ファイルの表）。差し替えは `file` を書き換えるだけです。
  まだ音が無いものは `file: null`（鳴らさず、コンソールに「SE未設定」と出るだけ）。
- どこで鳴らすか: クリックポイント等は `spots.json` / `views.json` / `gimmicks.json` の `{ "type": "se", "id": "キー名" }`、
  パートクリア時は `playParts.json` の `clearSE`、所持品・ヘッダーアイコンは `audio.json` の `ui`、ストーリーは `storyParts.json` の行の `se`。
- BGM: 操作パートは `playParts.json` の `bgm`（無いパートは直前のパートを引き継ぐ）、ストーリーは `storyParts.json` の行の `bgm`、
  オーディオの選曲は `bgm.json` の `sound`（ストーリーで流れたBGMは、`sound` が一致するトラックがオーディオに追加される）。
- BGM名: `audio.json` の `bgm` の各キーの `name`。`null` の間はファイル名から `BGM_` を除いた先頭6文字を暫定表示（例: The Da）。
- 音量: `audio.json` の `volume` は設定が「中」の時の音量（0〜1、省略時0.6）。音声ごとに元の音の大きさが違う場合はここで揃える。
  大=1.5倍(最大1)・小=0.5倍・消=無音。
- SE/BGMの音量(大・中・小・消)は設定画面から（セーブデータとは別に保存。以前のON/OFF設定は ON→中・OFF→消 で引き継ぐ）。著作権表記は `data/credits.json`。
- `node debug/rules.test.mjs` の D-06 で、未登録のキー・存在しないファイルを検出できます。

## セーブ/リロードの仕様

- 操作パート: アクション完了・視点移動の直後に自動保存し、リロードするとその状態から再開します。
- ストーリーパート: 途中でリロードした場合は、**そのストーリーパートを最初から再生します**（正式仕様）。
- エンディング後: リロードしてもエンディング画面のまま。「タイトルへ戻る」でセーブを消して最初からになります。
- ブラウザの設定（Cookie・サイトデータのブロック等）でlocalStorageが使えない環境では、セーブ無しで遊べます
  （設定画面に「セーブされません」と表示）。
- メッセージログはセーブしません（操作パート開始時にリセット）。1パート内でも最新200件までで、古いものから消えます。
- 同じゲームを複数のタブ/ウィンドウで開き、別のタブでゲームが進んだ場合、古いタブは操作・保存・BGMを止めて「再読み込み」を促します
  （古い状態でセーブを上書きしないため）。
- セーブデータが壊れている・書き換えられている場合、読める項目は補正して再開し、進行位置(パート・フェーズ)が不正なら破棄して最初からになります。
- セーブデータの大きさは通しプレイ後でも約1〜2KB（デバッグで4KB未満を確認）。SE/BGMの音量設定はセーブとは別のキーに保存します。

## デバッグテスト

- ルール単体テスト（ブラウザ不要）: `node debug/rules.test.mjs`
- ブラウザテスト: `npm i playwright-core` の後、ローカルサーバーで配信した状態で `BASE_URL=<配信しているURL> node debug/e2e.test.cjs`
  （Google Chromeを使用。スクリーンショットは `debug/screenshots/` に保存。一部だけ実行する場合は `TEST_IDS=A-01,F-01` を併せて指定。
  全件で約15分。SE/BGMはページ内で再生を記録し、BGMの二重再生・SEの鳴り方も検証します）
- テスト項目と結果の一覧は `設計資料/設計時メモ/デバッグケース_2026-09-26.txt`
