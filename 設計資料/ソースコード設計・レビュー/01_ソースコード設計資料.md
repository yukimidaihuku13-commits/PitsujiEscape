## 1. システム概要

| 項目 | 内容 |
|---|---|
| 種別 | ブラウザで動くポイント＆クリック型の脱出ゲーム（スマホ縦画面想定・最大幅 480px） |
| 構成 | 静的ファイルのみ（HTML + CSS + ES Modules）。**ビルド工程・外部ライブラリ・サーバー側処理なし** |

## 2. 設計方針（設計意図）

ソース中のコメントと構造から読み取れる設計意図を整理する。

### 2.1 データ駆動（「アイテムごと・スポットごとの個別コードを書かない」）
- クリックポイント（spot）の挙動は `spots.json` の **ルール配列**（`when` 条件 → `actions`）で表現し、JS 側は汎用エンジンのみを持つ。
- アイテムの「消失／変化／残存」は `items.json` の `persistence` で宣言し、`Inventory.js` が一括で処理する（`Inventory.js:1-3` のコメント「バグを減らす設計の核」）。
- 音声ファイルの割り当ては `audio.json` に集約し、未入手素材は `file: null` として後から差し替えられるようにしている。
- 意図: 仕様変更（文言・分岐・素材）の大半を JSON の編集だけで吸収し、ロジックのバグ混入箇所を減らす。

### 2.2 唯一の状態（Single Source of Truth）
- 進行状態はすべて `GameState`（`js/state/GameState.js`）の 1 オブジェクトに持ち、**それ以外の場所に進行状態を持たない** ことをルールとしている（同ファイル冒頭コメント）。
- セーブはこのオブジェクトをまるごと JSON 化して上書きする（差分保存しない）。
- 一時的な UI 状態（選択中アイテム `ctx.selectedItemId`、メッセージキュー、タップガード等）は **意図的に GameState の外**（`main.js` のクロージャ変数）に置き、セーブ対象から外している（`GameState.js:41-42`）。

### 2.3 ロジックと描画の分離
- `Engine`（`js/engine/ActionExec.js`）は DOM に一切触れず、`ui` コールバック経由でのみ画面に作用する。
  → Node.js 上でブラウザなしにルール全分岐をテストできる（`debug/rules.test.mjs`）。
- `Renderer`（`js/ui/Renderer.js`）は状態を **読むだけ** で画面を再構築し、状態を変更しない。
- `main.js` は両者を繋ぐ「配線」役（冒頭コメント）。

### 2.4 単純さ優先の全再描画
- 画面更新は毎回 `root.innerHTML = ""` → DOM を作り直す方式（仮想 DOM や差分更新なし）。
- 意図: 試作段階で画面仕様が頻繁に変わるため、描画の整合性バグ（古い表示が残る等）を構造的に起こさない。

### 2.5 演出順序の一元管理（メッセージキュー）
- メッセージだけでなく「画像表示」「効果音」「フラグ切替」「ギミック起動」も同じキュー（`MessageQueue`）に積み、**資料に書かれた順番どおり 1 つずつ** 見せる。

### 2.6 防御的設計（壊れても止まらない）
- 画像欠落 → 文字のプレースホルダーへ自動切替（`onerror`）。
- セーブ破損・改ざん・旧バージョン → 読み込み時に正規化、不正なら破棄して最初から（`normalizeLoadedState`）。
- `localStorage` が使えない環境 → セーブなしで続行し、設定画面に警告。
- データ取得の無応答 → 20 秒でタイムアウトし再読み込みボタンを表示。
- 連打・多重タップ → 画面切替直後 250ms のタップガード、キュー処理中の入力制御。
- 複数タブ → 他タブで進行したら自タブを読み取り専用化し再読み込みを促す。

### 2.7 外部へのリンクを行わない
- ゲーム内から外部サイトへのリンク（`<a href>`・画面遷移）は一切設けない。
- 著作権表記はサイト名のみを文字で記載する（内容は `assets/著作権表記.txt` の「以下著作権表記」。URL は同ファイルのメモ欄にのみ記録し、ソース・データには載せない）。
- 意図: 利用者を意図せずゲーム外へ遷移させない。外部 URL を扱う処理自体を持たないことで、URL の検証漏れ等の問題が起きる余地をなくす。

### 2.8 デバッグ機能の同居
- 直接ジャンプ、ホットスポット枠表示、ギミック正解表示を定数フラグで切り替え（リリース前に `false` にする前提）。

## 4. モジュール構成と依存関係

```
                         ┌──────────────────────────── main.js（配線） ────────────────────────────┐
                         │ データ読込 / normalizeLoadedState / 入力制御 / モーダル / BGM優先度 / 起動 │
                         └───┬──────────┬──────────┬───────────┬───────────┬──────────┬──────────┘
                             │          │          │           │           │          │
                         Engine     Renderer   MessageQueue  AudioManager  SaveManager  gimmick/*
                    (ActionExec)   (ui/Renderer) (ui/DialogueBox)  │ BgmName      │     (5種・DOMのみ)
                        │   │   │        │                                    │
          ┌─────────────┘   │   └──────┐ │                                GameState
          ▼                 ▼          ▼ ▼                              (SAVE_VERSION)
   RuleResolver ──▶ ConditionEval ◀── Navigator
          ▲                              ▲
       Inventory（Engine から使用）   Renderer も getArrowsForView / resolveBackground / hasMatchingRule を使用
```

- 依存方向は **main → (Engine, Renderer, Audio, Save, Gimmick) → (RuleResolver, Navigator, Inventory) → ConditionEval** の一方向で、循環依存はない。
- `Engine` → `SaveManager` の依存があり、Engine 内で保存タイミングを決めている（`runActions` 完了時、パート遷移時）。
- ギミック UI は `onResult(correct, input)` コールバックのみで Engine と疎結合（ギミックは正誤判定と表示のみ、結果処理は `Engine.resolveGimmickResult`）。

## 5. モジュール詳細

### 5.1 main.js（エントリーポイント）
`main()` 1 関数のクロージャ内に全 UI 制御をまとめている。主な構成要素:

| 区分 | 関数・変数 | 役割 |
|---|---|---|
| データ読込 | `fetchJson` / `loadAllData` / `keyBy` | 20 秒タイムアウト付き fetch。配列 JSON を `id`（hints は `playPart`）で辞書化 |
| セーブ補正 | `normalizeLoadedState` | 項目欠落補完・型補正・存在しない view/アイテム/BGM の除去。進行位置不正なら `null`（破棄） |
| キュー | `msgQueue` / `storyQueue` | 操作パート用（text/image/se/flag/gimmick）とストーリー用 |
| UI 橋渡し | `ui` オブジェクト | Engine に渡すコールバック群（queueMessage, playSE, setFlagInOrder, openGimmick 等） |
| 入力制御 | ルート要素のキャプチャ段階 click リスナー（1070-1108） | タップガード、開始時メッセージ中の操作禁止、メッセージ送り優先、自動クリア待ち |
| BGM | `baseBgm` / `imageBgmTrack` / `storyBgmOverride` / `refreshBgm` | 流す曲の優先度決定（5.1.1） |
| モーダル | `showItemZoom` / `openGimmick` / `openQueuedImage` / `openBgmMenu` / `showLogModal` / `showHintModal` / `showSettingsModal` | 各モーダル UI の構築 |
| 進行 | `enterStoryPart` / `enterPlayPart` / `startGame` / `renderEnding` / `jumpTo*` | 画面遷移の入口 |
| 多重タブ | `storage` イベント | 他タブのセーブ更新で読み取り専用化 |

#### 5.1.1 BGM の優先順位（`refreshBgm`）
1. 画像表示中だけ流す BGM（`imageBgmTrack`：パーティー画像等）
2. ストーリー中に行で BGM 指定があった後（`storyBgmOverride`）→ ストーリーの BGM
3. オーディオで選んだ曲（`currentTrack` が `default` 以外）
4. 操作パート / ストーリーの基本 BGM（`baseBgm` = `playParts.json` の `bgm`、無ければ直前パートを継承）

#### 5.1.2 入力制御の判定表（ルート click キャプチャ）
| 条件（上から順に判定） | 動作 |
|---|---|
| 設定ボタン | 常に通す |
| タップガード期間中（画面切替・モーダル閉じ直後 250ms） | 無視 |
| 操作パートの開始時メッセージ表示中 | ヘッダー以外のタップはメッセージ送り。ヘッダー（ログ/ヒント）は無反応 |
| ヘッダーアイコン / 早送りボタン | そのまま通す |
| 自動クリア待ち | メッセージ送りのみ |
| メッセージ表示中 & スポット/矢印/所持品/ノート等をタップ & 後ろに画像・ギミック・フラグが無い | キューを破棄して、そのタップの操作をそのまま実行 |
| メッセージ表示中（上記以外） | メッセージ送り |
| ストーリー表示中 | 次の行へ |

### 5.2 Engine（js/engine/ActionExec.js）
| メソッド | 役割 |
|---|---|
| `runActions(actions, spotId)` | アクション列を順に実行 → 再描画要求 → **保存** → 自動クリア判定 |
| `runAction(action, spotId)` | アクション 1 件を type で分岐実行（6.3 の一覧） |
| `openNote` / `showNotePage` | 調査ノート（`layoutType:"note"` の view）を開く／ページ表示と onShow 実行 |
| `attemptPartClear` | 配信用カメラ等。クリア条件判定 → クリア台詞 → 自動クリア経由でストーリーへ／未達メッセージ |
| `checkAutoClear` / `runAutoClear` | `autoClear:true` のパート（6）で、条件達成後メッセージを読み終えたら遷移 |
| `clearCurrentPart` | 残存アイテム破棄・選択解除・ノートページ初期化・部屋の色(tintFlag)リセット → ストーリーへ |
| `goToStoryPart` / `advanceToPlayPart` | フェーズ遷移。最後のストーリー後（`nextPlayPart:null`）はエンディング |
| `resolveGimmickResult` | ギミック結果。`failCases` 一致 → 個別処理、正解 → モーダルを閉じて onSuccess、不正解 → onFail |

### 5.3 ConditionEval / RuleResolver
- `evaluate(cond, state, ctx)`：副作用なしの条件評価。`{}` は常に真。`allOf`/`anyOf` で合成。
- `resolveActions(spot)`：**先頭から評価して最初に一致したルール** の actions を返す。一致なしは `defaultMessage` または「今は何も起きない」。
- `hasMatchingRule(spot)`：一致ルールが無い spot は画面に出さない（Renderer が使用）。
- `resolveMessage(def)`：`"文言"` / `["文言",…]` / `[{when,text|texts},…]` の 3 書式を解決。
- `resolveBackground(view)`：`backgroundVariants` の条件付き背景差分。

### 5.4 Navigator / Inventory / SaveManager / GameState
- **Navigator**：`moveToView` は存在チェック・`accessCondition` チェックの上で `currentView` を差し替えるだけ（ズーム/ドア等の演出差は持たない）。`getArrowsForView` は `transitions.json` から条件を満たす矢印を返す。
- **Inventory**：`giveItem`（重複防止・入手履歴記録）、`consumeSelectedItem`（使用履歴記録 → persistence に応じ消失/変化/残存。**`usableOn` に無い場所(不正解位置)では消費せず選択も残す**安全策あり）、`consumeItem`、`discardRemainInPartItems`。
- **SaveManager**：キー `pitsujiEscapeGame_save`。`save` は readOnly 時に何もしない。`load` はバージョン不一致・パース失敗で破棄。`isAvailable` はプローブ書込で判定。すべて例外を握りつぶして継続。
- **GameState**：`SAVE_VERSION = 3`。項目は 7 章参照。

### 5.5 MessageQueue（js/ui/DialogueBox.js）
- `enqueue` → `advance`（1 件表示、空なら `renderFn(null)` と `onEmpty`）→ `clear`。
- `current` と `queue` を外部（main.js）から直接参照・操作している（`queue.splice(0)`、`queue.some(...)`）。

### 5.6 Renderer
| 関数 | 画面 |
|---|---|
| `renderStart` | スタート画面（＋デバッグ用直接ジャンプ） |
| `renderPlay` | 操作パート：ヘッダー / 所持品バー（オーバーレイ）/ 背景 img / 色オーバーレイ / ホットスポット / 矢印 / フッター（表情＋メッセージ） |
| `renderNote`（内部） | 調査ノート（ページ画像ボタン＋閉じる） |
| `renderStory` | ストーリー：背景 / 立ち絵（複数可・noPortrait）/ 話者＋早送り / 本文 |
| `renderEnding` | 仮エンディング |
| `renderModalWrap` | モーダルの枠（overlay + box）を返す |

- spot に `position`（% 座標）があれば背景上のホットスポット、無ければ縦並びボタンとして表示（段階的な座標合わせを可能にする意図）。

### 5.7 AudioManager / BgmName
- 実音量 = 音声ごとの「中」音量（`audio.json` の `volume`、省略時 0.6）× 段階倍率（大1.5/中1/小0.5/消0、上限1）。
- BGM は常に 1 曲。同一キーの再要求は無視（頭出ししない）。
- 自動再生制限（`NotAllowedError`）時のみ、次の `pointerdown` で再試行。
- `setSuspended(reason)` で「タブ非表示」「他タブ進行」の一時停止を理由別に管理。
- 同一 SE の 80ms 以内の連続再生は抑止。
- BGM 名は `audio.json` の `name`、未設定なら キー名から `BGM_` を除いた先頭 6 文字。

### 5.8 ギミック UI（js/gimmick/*.js）
共通インターフェース: `renderXxxGimmick(container, gimmickDef, onResult[, onClose])`。内部状態はクロージャ変数、変更の度に `draw()` で全再構築。

| type | ファイル | 判定 |
|---|---|---|
| `numericCode` | NumericCodeGimmick.js | 桁数一致で決定可。`selector`（果物）付きは「正解の果物を選んだ状態で answer」が正解 |
| `letterSelect` | LetterSelectGimmick.js | 各行 1 文字を選び連結した文字列が answer と一致 |
| `tapRegions` | TapRegionsGimmick.js | 全正解範囲を見つけたら決定可（見つけた範囲は解除されない） |
| `chatSelect` | ChatSelectGimmick.js | 送り先選択 → 穴埋め全問正解 → 写真添付 → 送信 |
| `phoneDial` | PhoneDialGimmick.js | 発信番号 == answer。不正解時は入力値を返し `failCases` で個別処理 |

### 6.2 条件式（`when` / `clearCondition` / `accessCondition` 等）
| キー | 例 | 意味 |
|---|---|---|
| `{}` | `{}` | 常に真 |
| `allOf` / `anyOf` | `{"allOf":[…]}` | AND / OR |
| `playPart` | `3` / `{"gte":2}` | 操作パート番号（eq/gt/gte/lt/lte） |
| `flag` | `{"doorBUnlocked":true}` | フラグ（真偽比較） |
| `selectedItem` / `notSelectedItem` | `"itemChocolate"` | 選択中アイテム |
| `hasItem` / `everObtained` | `"itemPhoto"` | 所持中 / 一度でも入手 |

## 8. 主要処理フロー

### 8.1 起動
```
main()
 ├ loadAllData()  … 8ファイル並列 → transitions / audio / credits を順次
 │   └ 失敗: エラー文＋再読み込みボタン
 ├ SaveManager.isAvailable()
 ├ state = normalizeLoadedState(SaveManager.load()) || createInitialState()
 ├ AudioManager.init(audio)
 └ phase で分岐: start → renderStartScreen / story → enterStoryPart（最初から再生）
                 end → renderEnding / play → refreshBgm, drawPlay, checkAutoClear（救済）
```

### 8.2 クリックポイントのタップ
```
click(capture) 入力制御 → onSpotTap(spotId)
 → resolveActions(spot, state, ctx)      … 先頭一致ルール
 → engine.runActions(actions, spotId)
     ├ runAction × n  … ui.queueMessage / ui.playSE / Inventory / Navigator …
     ├ ui.requestRender() → drawPlay()
     ├ SaveManager.save(state)
     └ checkAutoClear()
```

### 8.3 アイテムの使用
所持品タップ（選択）→ 対象スポットをタップ → ルールの `selectedItem` 条件に一致 → `consumeSelectedItem` → `itemUsageLog` 記録、persistence に応じて消失/変化/残存、選択解除。
所持品の再タップは「未選択→選択→拡大表示→選択解除」の 3 段階。
使用先が不正解位置（`usableOn` 以外）の場合はアイテムを消費しない。ルール側で `consumeSelectedItem` を正解位置にのみ書き、`Inventory.consumeSelectedItem` でも `usableOn` を再確認する二重の防止（テスト W-01〜W-03）。

### 8.3.1 アイテム入手時の拡大画像
`giveItem` / 変化アイテムの `consumeSelectedItem` で所持品に新しく加わったアイテムを `Engine.withObtainedItemZoom` が検出 → `ui.showObtainedItem` → `showImageModal`（メッセージキュー経由）で、資料の「取得」の位置の順番どおりに表示。画面タップ（開いた直後 250ms は無視）または × で閉じると次のメッセージへ進む。

### 8.4 ギミック
```
triggerGimmick → ui.openGimmick（メッセージ表示中ならキューの後ろへ）
 → openGimmick: モーダル生成、currentModalStatusEl をセット（以後のメッセージはモーダル内に表示）
 → 各ギミック UI → onResult(correct, input)
 → engine.resolveGimmickResult
     正解: closeGimmick → runActions(onSuccess)
     不正解: failCases 一致 → そのアクション / それ以外 → onFail（モーダル内に表示）
```

### 8.5 パートクリア〜ストーリー〜次パート
```
attemptPartClear
 ├ 条件未達: notYetMessage
 └ 達成: clearMessages をキュー → clearSE → scheduleAutoClear
        → メッセージ読了(onEmpty) → runPendingAutoClear → runAutoClear → clearCurrentPart
        → goToStoryPart(phase=story, 保存) → enterStoryPart(行をキューへ)
        → 全行読了 → unlockStoryBgms → advanceToPlayPart
             ├ nextPlayPart=null → phase=end → エンディング
             └ phase=play, currentView=startView, 保存 → enterPlayPart
                  → startMessages ＋「BGM 〇〇 がオーディオに追加された」
```
パート6は `autoClear:true` のため、条件達成時点で `checkAutoClear` から同じ経路に入る。

### 8.6 保存タイミング
| タイミング | 箇所 |
|---|---|
| アクション列完了時 | Engine.runActions |
| 矢印移動・ノートを閉じた時 | main.js onArrowTap / onNoteClose |
| 順番待ちフラグの適用時 | applyFlagNow |
| フェーズ遷移時 | clearCurrentPart / goToStoryPart / advanceToPlayPart / startGame |
| BGM 選曲・ヒント開封 | openBgmMenu / showHintModal |
| 音量設定 | AudioManager.setLevel（別キー `pitsujiEscapeGame_audioSettings`） |

ストーリー途中は保存しない（リロード時はそのストーリーを最初から再生する仕様）。

## 9. エラー処理・フォールバック方針

| 事象 | 対応 | 箇所 |
|---|---|---|
| JSON 取得失敗・タイムアウト | エラー表示＋再読み込みボタン | main.js:35-48, 111-125 |
| 背景・立ち絵・ノート・アイテム画像の欠落 | プレースホルダー文字 / エラーラベル | Renderer.js:17-27 ほか |
| セーブ破損・改ざん・旧バージョン | 正規化 or 破棄 | main.js:66-94, SaveManager.js:31-47 |
| localStorage 使用不可 | セーブなしで続行、設定画面に警告 | SaveManager.js 全般, main.js:910-915 |
| 未登録/未設定の音声 | 再生せずコンソール出力 | AudioManager.js:93-99 |
| 自動再生制限 | 次のタップで再試行 | AudioManager.js:153-172 |
| 存在しない spot/view/gimmick/パート | console.error して無処理 | main.js, Navigator.js, ActionExec.js |
| 未知のアクション type | console.warn | ActionExec.js:115-117 |
| 他タブで進行 | 読み取り専用化・BGM 停止・再読み込み促し | main.js:1112-1128 |
