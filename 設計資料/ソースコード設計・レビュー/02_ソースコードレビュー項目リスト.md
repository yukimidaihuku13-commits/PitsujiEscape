## 判定と重要度の定義

| 判定 | 意味 |
|---|---|
| OK | 問題なし（良い実装として記録するものを含む） |
| 指摘 | 修正・改善を推奨する |
| 要検討 | 仕様判断・運用判断が必要（コード単体では是非を決められない） |
| 対象外 | 本プロジェクトの構成上、該当しない |

| 重要度 | 基準 |
|---|---|
| 高 | リリース前に必ず対応すべき（不具合・情報露出・進行不能につながる） |
| 中 | 潜在不具合・保守性低下。早めの対応を推奨 |
| 低 | 改善提案・将来課題 |

### 「安全性」観点の定義
本資料では「セキュリティ（攻撃・改ざんへの耐性）」と区別し、**利用者・データ・運用を守る性質** を安全性として扱う。
具体的には「利用者のデータ（セーブ）を失わせない」「リリース時の事故（デバッグ機能の残存等）を防ぐ」「利用者の身体・利用環境への配慮（音量・光刺激・アクセシビリティ）」「開発運用ルール（秘密情報・ポート番号の非埋め込み）の順守」を対象とする。
